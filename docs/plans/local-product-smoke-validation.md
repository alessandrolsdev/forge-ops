- #119 — Validate local end-to-end product flow after auth and database bootstrap

## Goal

- database bootstrap working
- operator auth working
- backend protected routes reachable
- frontend reachable through the local proxy

### Required claims for local protected smoke
- Every protected route requires a valid bearer token with matching:
  - `iss = OPERATOR_AUTH_ISSUER`
  - `aud = OPERATOR_AUTH_AUDIENCE`
  - non-empty `sub`
  - valid `exp` and `nbf`
- The verifier accepts capabilities from either:
  - JWT `capabilities` array
  - JWT `scope` string
- Current route-level capability contract:
  - `GET /api/v1/repositories/discovery` -> auth only
  - `GET /api/v1/repositories` -> auth only
  - `POST /api/v1/repositories` -> auth + `repositories:write`
  - `GET /api/v1/repositories/:id/workflows` -> auth only

### Local token generation
Generate the token inside the backend container so the helper uses the same runtime env already loaded by Docker Compose:

```powershell
$token = docker compose exec -T backend node /workspace/scripts/generate-local-operator-token.mjs
```

Generate a read-only token if you only need protected GET routes:

```powershell
$token = docker compose exec -T backend node /workspace/scripts/generate-local-operator-token.mjs --capability repositories:read
```

Generate a token for onboarding and repository writes:

```powershell
$token = docker compose exec -T backend node /workspace/scripts/generate-local-operator-token.mjs --capability repositories:read --capability repositories:write
```

Use the token against the backend directly:

```powershell
Invoke-RestMethod -Method Get -Uri http://127.0.0.1:3333/api/v1/repositories/discovery -Headers @{ Authorization = "Bearer $token" }
```
